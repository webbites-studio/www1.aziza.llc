# Aziza Astana Concierge Portal

A responsive customer and administration portal for managing relocation requests, required documents, travel bookings, schedules, service estimates, and local recommendations in Astana, Kazakhstan.

- Pricing with indicative USD, EUR, and RUB conversion
- Curated areas, restaurants, and attractions
- Responsive desktop and mobile layouts
- Browser persistence through `localStorage`

## Technology

- TypeScript and the local `BaseComponent` framework
- Native browser DOM, events, storage, and ES modules
- BrowserSync development server and Node.js standard-library tests
- No runtime or UI package dependencies
- Multi-stage Docker build
- Unprivileged Nginx runtime

## Requirements

- Node.js 18 or later
- npm 9 or later
- Docker 29 or later for container deployment

## Authentication Mode

The portal currently uses local demo credentials and does not contact an identity provider. The framework OAuth2 implementation remains initialized and available under `src/auth/`, `src/services/`, and `src/state/` for later integration. The router keeps `/oauth/login` and `/auth/callback`; local portal routes use a separate temporary local-session guard.

## Temporary Local Data

`src/portal-data.ts` is intentionally a temporary local data source. It contains seed customers, portal option lists, fallback exchange rates, and translations so the frontend can operate without a backend. Once the backend and database become authoritative, this file can be removed after its data contracts are replaced by generated API types and service calls. Shared runtime state and persistence are isolated in `src/state/portal-state.ts` to keep that transition contained.

## Docker Deployment

Build the production image from the project root:

```bash
docker build -f deployment/docker/Dockerfile -t aziza-portal:latest .
```

Run the container:

```bash
docker run --rm -p 8080:8080 --name aziza-portal aziza-portal:latest
```

Open `http://localhost:8080`. Confirm container health with:

```bash
curl http://localhost:8080/health
docker inspect --format='{{.State.Health.Status}}' aziza-portal
```

The image uses Node only in the build stage. The final image serves compiled assets from `nginxinc/nginx-unprivileged` on port `8080`, includes immutable caching for fingerprinted assets, and falls back to `index.html` for client-side routes.

### Publishing an Image

Tag and push the image to your container registry:

```bash
docker tag aziza-portal:latest REGISTRY/ORGANIZATION/aziza-portal:VERSION
docker push REGISTRY/ORGANIZATION/aziza-portal:VERSION
```

Replace `REGISTRY`, `ORGANIZATION`, and `VERSION` with values for Docker Hub, GitHub Container Registry, Azure Container Registry, or another OCI-compatible registry.

## Data and Production Readiness

This repository is a functional frontend prototype. Customer records, credentials, schedules, prices, and uploaded files are stored in browser `localStorage`. This makes changes persistent in one browser but does not synchronize them between users or devices.

Before handling real customer or immigration documents in production:

1. Replace demo authentication with a server-side identity provider and secure sessions.
2. Store customer records in an access-controlled database.
3. Upload files to encrypted private object storage using short-lived signed URLs.
4. Add authorization checks on every server endpoint and document operation.
5. Add audit logs, retention rules, malware scanning, backups, and privacy controls.
6. Source exchange rates from a maintained provider and display their effective date.

The Docker image currently serves the frontend only. Backend APIs and storage should be deployed separately and configured through environment-specific application settings.
